# WeasyPrint upstream review

Reviewed 2026-11-14 against the integration's pinned WeasyPrint **70.0**. The [stable documentation](https://doc.courtbouillon.org/weasyprint/stable/) currently identifies itself as 70.0. This review used upstream issues, maintainer comments, release notes and versioned documentation. An upstream report is not a local reproduction; those distinctions appear below. See [setup and isolation](WEASYPRINT.md) and [measured renderer comparisons](RENDERER_BENCHMARKS.md) for the implementation and local results.

## Tagging and conformance boundaries

[Multiple simultaneous PDF variants remain an open request (#2783)](https://github.com/Kozea/WeasyPrint/issues/2783). The integration selects `pdf/a-4f` with tags enabled. This is not a blanket PDF/UA conformance claim. Upstream also warns that selecting a variant does not guarantee conformance and that HTML structure, language, title and ordering affect accessibility. Validate the final EA-PDF after Java imports and metadata processing; keep human reading-order review separate from machine checks. [Specialized PDF documentation](https://doc.courtbouillon.org/weasyprint/v70.0/common_use_cases.html#generate-specialized-pdfs).

[The PDF/UA improvement tracker (#2482)](https://github.com/Kozea/WeasyPrint/issues/2482) still lists unfinished areas. In particular, [`aria-hidden`/role handling (#2550)](https://github.com/Kozea/WeasyPrint/issues/2550) is open: authored decorative images may remain Figures requiring alternate text. Do not assume that adding ARIA attributes makes decorative content an Artifact. A future decorative-content policy needs explicit semantic tests.

## Documentation review and deferred improvements

The [70.0 security guidance](https://doc.courtbouillon.org/weasyprint/v70.0/first_steps.html#security) explicitly covers CPU/memory exhaustion, huge CSS values, filesystem disclosure, attachments and SVG subresources. Its HTTP timeout is not a whole-render deadline. The current design therefore retains OS isolation, a restrictive fetcher, fatal resource errors, subprocess limits and parent-enforced cancellation. Input-size limits alone are insufficient.

The [API contract](https://doc.courtbouillon.org/weasyprint/v70.0/api_reference.html#api-stability) excludes private internals from compatibility guarantees. The EA-PDF marker bridge and width inspection use private internals, so the exact pin and targeted tag/layout tests are required upgrade gates. Replacing either with an upstream public extension point would reduce maintenance risk; no such API change is implemented here.

Two performance options merit separate measurement, not default changes:

- A job-local disk image cache is a documented [public API option](https://doc.courtbouillon.org/weasyprint/v70.0/api_reference.html#weasyprint.DEFAULT_OPTIONS). It could reduce image-cache RSS at the cost of I/O and disk usage. It would need the same cleanup, disk bounds and cancellation coverage as other job files.
- Upstream [performance guidance](https://doc.courtbouillon.org/weasyprint/v70.0/common_use_cases.html#improve-rendering-speed-and-memory-use) notes costly CSS cascades and multi-page tables, and the time/size trade-off from image/font optimization. Shared caches or long-lived workers could save startup work, but would change resource ownership and isolation. They are not enabled by this review.

No new renderer features, upstream patches, runtime pooling or CSS rewrites were implemented as part of this review. Priorities above are follow-up recommendations, except for the explicitly identified integration mitigations.
